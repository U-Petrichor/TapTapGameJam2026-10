# 阶段检查点存档（第一版）

保存字段：version、dayIndex、phase、coins、nutrition、talentPoint。
天赋、装备、背包和世界状态尚未保存，当前版本用于验证基础流程。

## 工作方式

- SaveManager 为静态类，不需要挂到场景。
- GamePhaseManager 等待一帧，让所有 Start 初始化完成，再开始新游戏或消费主菜单传入的读档请求。
- 正常 EnterPhase 在阶段事件及新一天事件处理完成后保存检查点。
- 白天和夜晚退出时不另存资源，继续时整组恢复阶段入口快照，计时恢复完整阶段时长。
- 购物阶段的操作也暂不另存；进入夜晚时才提交购物结果。
- 继续游戏跳过开场视频，保留加载界面；直接在编辑器运行 GameScene 按新游戏处理，会建立新的检查点。
- 新游戏在第一天初始化完成时替换主存档。
- 恢复天数不经过 EnterPhase，避免 DayIndex 再加一；发布当天事件以重建日期相关场景条件，再发布阶段事件。
- GameManager 随游戏场景销毁，避免重新进入时继续使用上一场景的玩家引用。

## 文件

Application.persistentDataPath/save.json。临时文件为 save.json.tmp，备份为 save.json.bak。
写入临时文件后替换主文件，读取时验证版本、日期、阶段及资源范围；主文件不可用时尝试备份。
不会读取 tmp 文件。保存失败会输出错误；不会因此中断阶段切换。

## Unity 手动验证

1. 从主菜单开始新游戏，确认第一天、白天；检查 save.json 六项业务数据与阶段开始值一致。
2. 白天获得资源，未切阶段即返回主菜单，点继续：资源回到白天检查点，天数不变，白天计时重置。
3. 完成白天进入购物，记录四项资源和天数；继续游戏应回到购物，计时停止。
4. 购物消费后进入夜晚，再继续：资源为夜晚开始值、天数不变，夜晚过渡结束后正常计时。
5. 完成夜晚进入下一天，确认日期只加一；读档后不再增加。
6. 连续返回主菜单并继续两次，确认玩家操作、阶段和 UI 都正常，无 MissingReferenceException。
7. 保留有效 bak 后破坏主 JSON，确认继续按钮仍可用并能读取备份；两份均不可用时按钮禁用。
8. 确认天赋、装备等尚未持久化，测试时不要把本版当作完整游戏存档。

## 后续扩展

在 SaveData 中添加天赋、装备数据并提升版本，提供迁移策略；同一检查点统一采集和恢复全部模块，避免跨时间点混合资源与物品。

## 玩家全局存档

PlayerProfile 将 version、hasWatchedIntro 和 seenTutorialSteps 独立保存在 persistentDataPath/profile.json。
与 save.json 分开，新游戏不清除此记录，也不依赖关卡存档是否存在。
hasWatchedIntro 只是兼容旧字段；实际判断统一走 seenTutorialSteps 里的 `intro.video`。
所有“首次出现”的教程步骤也记录在 seenTutorialSteps，整个安装只出现一次。
首次点击开始游戏会播放视频；正常播完并成功载入游戏后才写入已观看标记。
此后点击开始游戏直接加载，继续游戏始终直接加载。仍保留原来的加载遮罩及输入、暂停恢复流程。
播放失败、超时、未播完退出不会写入标记，下次开始游戏仍会尝试播放。

验证：无 profile 时开始游戏应播放；播完后返回菜单再次开始应跳过；重启应用后也应跳过；
删除关卡存档再开始仍应跳过；视频异常时不应生成已观看标记；继续游戏应恢复阶段且不播放视频。
开发时想重新测试首次体验，退出运行后删除 profile.json 及 profile.json.bak，保留 save.json 即可。
也可以用编辑器菜单 `Tools/Tutorial/Reset Tutorial Progress` 清空全部“第一次”记录。
