# 阶段检查点存档（完整版 v2）

保存字段：version、dayIndex、phase、coins、nutrition、talentPoint、每日结算信息，以及以下完整状态：

- hasCollectedAccessCard：本局是否拾取过门禁卡；读档恢复目标门的授权，已拾取后不会在第二/第四晚重复刷新，不重放首次开门表现。与其他数据一起按阶段检查点提交。旧存档缺少该字段时视为未拾取。
- talents：稳定天赋 ID 与等级，恢复时不重新消费或退还天赋点。
- sharedNutrition：蟑螂实际使用的浮点共享营养池，与 PlayerResources.Nutrition 分别保存。
- nests：场景巢穴稳定 ID、位置、旋转、解锁状态、巢内蟑螂数、产卵/首次孵化进度、已投入孵化营养和当前指令。
- items：玩家背包、仓库和已装备物品；保存模板 ID、容器、背包格子与旋转、仓库格子、装备槽及食物剩余营养。

存档仍为整组阶段入口检查点，不保存阶段中途进度。读档后所有模块一起回到阶段入口；购物中途退出也会回滚该阶段内的购买和天赋操作，进入夜晚才提交。
地图散落物、随机夜间掉落、商店货架、玩家生命/体力、敌人和信息素不在本轮存档范围内；夜间物品仍按现有阶段流程生成。

## 工作方式

- SaveManager 为静态类，不需要挂到场景。
- GamePhaseManager 等待一帧，让所有 Start 初始化完成，再开始新游戏或消费主菜单传入的读档请求。
- 正常 EnterPhase 在阶段事件及新一天事件处理完成后保存检查点。
- 白天和夜晚退出时不另存资源，继续时整组恢复阶段入口快照，计时恢复完整阶段时长。
- 购物阶段的操作也暂不另存；进入夜晚时才提交购物结果。
- 继续游戏跳过开场视频，保留加载界面；直接在编辑器运行 GameScene 按新游戏处理，会建立新的检查点。
- 新游戏在第一天初始化完成时替换主存档。
- 恢复天数不经过 EnterPhase，避免 DayIndex 再加一；发布当天事件以重建日期相关场景条件，再发布阶段事件。
- GameManager 随游戏场景销毁，避免重新进入时继续使用上一场景的玩家引用。

## 文件

Application.persistentDataPath/save.json。临时文件为 save.json.tmp，备份为 save.json.bak。
写入临时文件后替换主文件，读取时验证版本、日期、阶段、资源范围及新增列表/枚举/数值合法性；主文件不可用时尝试备份。
不会读取 tmp 文件。保存失败会输出错误；不会因此中断阶段切换。

## Unity 手动验证

1. 从主菜单开始新游戏，确认第一天、白天；检查 save.json 六项业务数据与阶段开始值一致。
2. 白天获得资源，未切阶段即返回主菜单，点继续：资源回到白天检查点，天数不变，白天计时重置。
3. 完成白天进入购物，记录四项资源和天数；继续游戏应回到购物，计时停止。
4. 购物消费后进入夜晚，再继续：资源为夜晚开始值、天数不变，夜晚过渡结束后正常计时。
5. 完成夜晚进入下一天，确认日期只加一；读档后不再增加。
6. 连续返回主菜单并继续两次，确认玩家操作、阶段和 UI 都正常，无 MissingReferenceException。
7. 保留有效 bak 后破坏主 JSON，确认继续按钮仍可用并能读取备份；两份均不可用时按钮禁用。
8. 在背包中旋转并摆放食物、工具和装扮，在仓库各分类页留空洞并放入物品，穿戴装备；切阶段后继续，确认物品、槽位和效果一致。
9. 先消耗部分食物营养再存档，读档后丢回地上，确认不会变回满营养。
10. 搬动巢穴，保留不同解锁/首次孵化进度，生成不同数量蟑螂；切阶段后重复继续两次，确认位置、状态、数量和共享营养一致。

## 模板与版本兼容

`Assets/Resources/SaveItemCatalog.asset` 保存物品 ID 到预制体组件的映射。ID 使用资产 GUID + 组件 local file ID，改名、移动资产不影响。编辑器重新加载、开始运行及构建前自动刷新；也可运行 `Tools/Save/Rebuild Item Catalog`。新增可拥有物品请使用预制体，避免直接在场景里新建无模板的物品。

场景现有巢穴已写入独立 `_saveId`，搬运、重排 Hierarchy 不改变标识；保存场景时会给新巢穴或复制产生的重复 ID 自动生成新 ID。不要清除已发布场景的巢穴 ID。

v1 存档继续可读；其未保存的天赋、物品和巢穴状态采用场景默认值。下次阶段保存升级为 v2，无法追回旧版本未记录的进度。未知未来版本及不完整 v2 数据会被拒绝，并尝试备份。

## 自动验证

Unity 菜单 `Tools/Save/Run Full Save Checks` 会启动 GameScene，构造天赋、三类背包/仓库物品、装备、剩余食物和巢穴状态，对白天、购物、夜晚各重复读档两次，再验证主文件损坏回退、双文件损坏拒绝和 v1 兼容。运行前退出 Play Mode；检查使用 `Temp/FullSaveTestData` 独立目录，不会改写玩家真实 save.json，结束自动退出运行模式。报告位于 `Temp/FullSaveChecks.txt`。

## 玩家全局存档

PlayerProfile 将 version、hasWatchedIntro 和 seenTutorialSteps 独立保存在 persistentDataPath/profile.json。
与 save.json 分开，新游戏不清除此记录，也不依赖关卡存档是否存在。
hasWatchedIntro 只是兼容旧字段；实际判断统一走 seenTutorialSteps 里的 `intro.video`。
所有“首次出现”的教程步骤也记录在 seenTutorialSteps，整个安装只出现一次。
首次点击开始游戏会播放视频；正常播完并成功载入游戏后才写入已观看标记。
此后点击开始游戏直接加载，继续游戏始终直接加载。仍保留原来的加载遮罩及输入、暂停恢复流程。
播放失败、超时、未播完退出不会写入标记，下次开始游戏仍会尝试播放。

验证：无 profile 时开始游戏应播放；播完后返回菜单再次开始应跳过；重启应用后也应跳过；
删除关卡存档再开始仍应跳过；视频异常时不应生成已观看标记；继续游戏应恢复阶段且不播放视频。
开发时想重新测试首次体验，退出运行后删除 profile.json 及 profile.json.bak，保留 save.json 即可。
也可以用编辑器菜单 `Tools/Tutorial/Reset Tutorial Progress` 清空全部“第一次”记录。
