# 小游戏重构与新玩法（2026-10-08）

## 任务架构

- `MiniGameCandidate / Quest`：Inspector 配置奖励，判断生成条件，创建新实例。
- `MiniGameInstanceBasic`：抽象基类，奖励为每个实例的只读数据；成功、取消、清理及结束通知统一处理。
- 具体 `Instance`：管理交互点与阶段；`PanelMiniGameInstance` 复用面板任务的订阅、占用和释放。
- `MiniGameContent`：承载面板玩法。面板给内容绑定本次交互玩家，完成后通知实例。

分拣文件、倒狗粮、清理、炒股、咖啡分别拥有具体实例；送文件沿用两阶段实例并接入统一结算。
送文件实例统一命名为 `DeliveryFileInstance`。
普通小游戏关闭只结束一次尝试，任务仍保留；取消任务会释放交互点并关闭该任务的面板。
关闭请求带点位身份，旧任务的关闭请求和完成回调不能影响后来打开的任务。

## 已确定的玩法

### 清理垃圾（MiniGameKind.Clean）

按住鼠标左键在污渍上滑动，达到原始污渍面积的 90% 即完成。
只统计原本非透明像素；重复擦同一位置不重复计数；快速移动沿线段连续擦除。
`CleanGame` 的 `_completionThreshold` 默认 0.9，`_brushRadius` 默认 35 个 UI 单位。
`_stainTexture` 可以替换为带透明背景的污渍图片；程序通过 GPU 读取，不要求导入资源开启 Read/Write。
背景替换 `CleaningSurface` 的 Image；笔刷、进度文字、进度条均可在 Inspector 调整。
无污渍资源时使用程序生成的占位污渍。擦除工作纹理分辨率为 384×216。
取消后再次打开从零开始；原始图片资产不会被修改。

### 模拟炒股（MiniGameKind.StockTrade）

每一个价格点，包括第一点，独立随机从闭区间 `[50, 200]` 取整数。
买一只、买全部、卖全部都在当前价格点执行；只有等待推进价格点。
全部买入数量向下取整，买卖使用玩家实际金币；不允许资金不足买入、负数量或卖空。
图中只显示已经产生的价格点，隐藏纵轴上下限标记，横轴最多 5 点；每个点下方显示该点的历史价格，最新价格不再单独放在上方状态栏。
第 5 点立即强制清仓，交易按钮禁用；显示结果后，「等待」按钮变为「完成」。
炒股现在是白天固定入口，不参与随机刷新。`StockInstance` 的寿命覆盖整个白天，用于维持椅子的交互和任务箭头；前两次完成或提前关闭保留活动实例，第三次结束后关闭当天入口。
每次进入创建新的独立轮次，从第一个随机价格点开始，最多 5 点，每天最多进入 3 次。
离开白天或游戏结束时清仓、关闭面板并移除指引；下一天立即恢复入口与指引。

### 制作咖啡（MiniGameKind.MakeCoffee）

使用统一 2D 面板；`MakeCoffeeQuest → MakeCoffeeInstance → MakeCoffeePoint → CoffeeGame` 接入任务系统。玩法只有三步：长按准备好的研磨机 1.5 秒、把研磨机下方的粉杯拖到中央杯子上、把右侧热水壶拖到杯子上方并按住注水 2 秒。
器具可以替换 Image 的 Sprite，保持 RectTransform 和字段引用即可。旧的 `CoffeeMinigameManager` 与 `CoffeeDeskInteractor` 已删除，主场景不再依赖旧 3D 咖啡链路。
成功结算由 `MakeCoffeeInstance` 发放配置奖励，并额外增加一份咖啡；取消、退出不发放咖啡。

## 自行决定并记录的事项

1. 炒股提前退出或面板关闭：按当前价格清仓，保留已发生的实际盈亏并结束本局，当天还有次数时可立即再次进入；阶段切换、活动取消或对象禁用则同时释放指引和入口。
2. 炒股固定活动不发放额外任务奖励，交易盈亏直接体现在钱包中；日间实例负责入口与位置指引。
3. 清理与 2D 咖啡默认奖励各为 30 金币、1 天赋点；送文件保留 1 金币、5 天赋点；旧分拣、倒狗粮沿用配置。
4. 炒股第 5 点先展示结算摘要，用户点击「完成」再关闭面板；此时持仓已经清空，不能继续交易。
5. 炒股入口使用用户已替换的椅子，保留 `StockPoint` 的位置、模型和交互引用。初次配置时的方块仅是历史占位物，本次未重新生成它。
6. 清理与咖啡提前关闭后任务保留，再次打开重置玩法；所有小游戏继续使用世界倒计时，不暂停一天的进度。
7. 原场景在改动前保存到 `RecoverySnapshots/20261008-minigames/GameScene_before.unity`，包含用户已有的磁盘修改。
8. 没有调用美术生成服务；新面板使用可替换的程序占位图形。
9. 原输入脚本尝试切到不存在的 `MiniGameInstanceBasic` ActionMap，实际资产名是 `MiniGame`。已统一使用真实名称，保留旧调用名作为兼容入口。
10. 实测发现原移动脚本会在白天因夜晚网格尚未创建而反复触发 NUnit 断言。改为检查网格、蟑螂管理器及配置是否存在，不存在时跳过信息素写入；移动和夜晚信息素计算保持原有行为。
11. 原静态中文字库缺少新玩法使用的字符。新建 `MiniGameUI SDF` 动态字库，仅用于三个新面板，复用项目已有阿里巴巴普惠体源字体。

## 明确关闭和白天结束的资金结算

- 关闭按钮、Esc、白天结束或任务取消均经 StockGame.End → StockRound.Close，按当前价格一次性卖出全部持仓。
- 结算后的金币 = 退出前剩余金币 + 持仓数量 × 当前股票单价，持仓归零；不会生成新的价格，也不会恢复初始资金。
- 既有逻辑已符合要求，本次补充面板说明和验证。核心检查覆盖当前价 50、110、200 时的损失和收益，以及重复关闭不重复加钱。
- Play 检查新增带持仓结束白天，并覆盖面板先关闭、任务管理器先取消这两种事件处理顺序。
